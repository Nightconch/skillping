# 实时 Workflow 分批匹配

本文描述提取 v6 的单工作、单能力实时路径。历史导入和已保存的多关联记录保留原有含义。当前工作最终最多归属一个 Workflow。

## 候选集合与快照

`storage.reviewRows` 保留 scope、规范化工作区、保留状态和有效证据规则，按 Workflow ID 稳定枚举全部合格候选。确认、永久抑制和已有证据的保留规则不变。抑制、覆盖、静默及冷却仍约束推荐资格。

`prepareDecisionMatch` 冻结候选身份、完整原型、语义状态和当时的有效证据。词面前五项不再是实时匹配的唯一入口。全集保存在本地，工具每次只返回当前批次。

## Sqwish 扫描

启用且允许外发、匹配阈值已配置并通过隐私检查时，每个 HTTP 请求最多判断五个新候选。请求使用相同的当前工作、能力、判断规则、模型和配置。已淘汰候选不重新上传。本地只维护最高、次高候选的身份和分数。

`existence.threshold` 判断当前请求是否存在可复用工作。`matching.threshold` 判断候选是否达标。两者独立。只有全部候选的合法概率都低于匹配阈值，才能提交有效零命中并创建新 Workflow。任何批次缺失答案、失败、超时或预算耗尽，都丢弃该轮部分分数，改由主模型重新扫描完整冻结集合。

有至少两个候选时，正命中交给主模型读取最高与次高候选的全部具体证据，终审最多选择一个。精确同分、接近分数和语义不确定都经过这条证据路径。没有新增数值分差门槛，也不声称现有概率已经校准。仅一个候选且已有确认时，完整 Sqwish 判定可以直接关联；forming 候选达到当前推荐门槛时仍需证据确认。

## 主模型渐进复核

未启用 Sqwish、配置不完整或任一批失败时，使用原有 review v3 的 `same`、`different`、`uncertain`。不生成或比较主模型概率。

`request.scan.phase=scan` 表示当前批仍属暂定判断。第一批最多五项，后续批是暂定赢家加最多四个新候选；没有赢家时继续读取五个新候选。`same` 选择当前批中证据最充分的一个，`different` 排除当前完整批次，`uncertain` 安全结束且不增加归属计数。相同主题、工具或文件格式不能单独证明方法相同。证据无法区分两个候选时返回 `uncertain`，不能按目录顺序任选一个。

正常换批返回新的 `review_required` 和 `review_set_id`，不消耗纠错额度。候选目录和证据仍使用 `get_review_evidence` 与各自的游标。服务端只接受当前批中的候选，旧集合及游标不能授权新批次。

全集扫描结束后，有暂定赢家则返回 `scan.phase=final` 的证据终审。`same` 要求读完赢家证据；Sqwish 的终审要求读完最高与次高候选证据。证据尚未读完会返回正常续读包。若 Sqwish 的两个候选均被判为 `different`，重新开始完整主模型扫描，沿用剩余预算。主模型终审的反对或不确定结果不写入关联。

主模型扫描全部判为不同，才创建一个新 Workflow。中间暂定赢家不会产生关联、次数或推荐。确认使用历史证据加当前 proposed 证据，当前证据只在最终提交时加入。

## 有界行为与提交

| 范围 | 预算 |
| --- | --- |
| Hook 存在性检查 | 总计 6000 ms，保留 300 ms 返回时间，独立于提取后的匹配。 |
| Sqwish 全扫描 | 从准备前开始的单一 `match_timeout_ms`，默认 5000 ms、配置上限 10000 ms。每批只使用剩余时间。 |
| Sqwish 请求 | 单次完整 HTTP body 上限 16 KiB，累计上限 256 KiB，包含重复的当前工作与规则。 |
| 主模型复核 | 从暂存请求开始最多十分钟，换批及快照刷新不延长。 |
| 主模型返回载荷 | 每包沿用 6144 或 12288 的估算 token 硬上限，目标 4096；整个扫描与证据续读累计完整 JSON 不超过 256 KiB。 |

这些总载荷预算是本地资源上限，没有经过语义准确率校准。达到上限时返回 `budget_exceeded`，按 `uncertain` 结束。累计超限包附 `scan_limit_bytes`。不能把预算终止解释成零命中。

最终提交重新检查 generation、`decision_revision`、模型配置、检测和推荐开关、取消、有效期、完整候选集合及每个候选的语义和证据快照。generation 门禁包住最终短事务。HTTP 等待不持有 SQLite 写事务或清空门禁。快照变化最多使用既有一次刷新额度，重新扫描当前集合并沿用原截止时间及剩余主模型载荷预算。

请求身份和同 task 同规范化工作区的相同文本仍去重。最终只提交一次关联，单回合领取、抑制、冷却及清空协调保持现行约束。进程退出或未完成复核可以留下尚未关联的工作记录，不会把暂定赢家写成匹配证据。

## 验证边界

确定性检查使用隔离临时 SQLite、注入概率和主模型回答，覆盖后续候选、跨批最高分、换序、分组、零命中、同分、不确定、重复请求、失败、超时、取消、配置和证据变化及清空。仓库的 `plugins/skillping-runtime/verification/matching/README.md` 记录有限模型与可编译源码错误，计数和推荐生命周期另有独立验证。

这些检查证明指定输入下的扫描与提交行为。真实模型可能受候选顺序、分组和措辞影响，当前没有语义排序稳定性、召回准确率或在线延迟评估。独立 HTTP 需要重复当前工作和规则；主会话也可能保留旧工具结果。实现仅避免主动再次输出淘汰候选，没有测量或承诺 token、费用收益。README 中 2026-10-21 的 Sqwish 数据属于较早的单批实验。
